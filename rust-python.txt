L’addition

Ce que ça coûte, ce que ça rapporte

Ce qui coince
• Pas de génériques dans les classes: #[pyclass] struct Container<T>
• Pas de lifetime dans les classes: #[pyclass] struct Container<'a>
• Pas d’interop traits vers protocoles, par ex. Iterator ne devient pas itérable sans écrire manuellement les
__iter__ & __next__
• La génération des .pyi n’est pas automatique, Python typing hints, #5137
• Ne pas bloquer le GIL

23 / 26

Tips
• Réduire la surface d’interop
• Batcher, un appel pour 1 M d’éléments, pas 1 M d’appels
• maturin-import-hook ou un watcher comme bacon
• py.detach(...) sur les sections CPU-bound et les I/O bloquantes si on block_on
• Tester des deux côtés avec pytest et cargo test
• py-spy: le flamegraph peut voir les frames Rust
• Faire attention aux mesures de performance: --release

Quand ça vaut le coup
1. Optimisation: garder l’API Python, remplacer les modules à optimiser par du Rust. Par exemple Polars,
pydantic-core, …
2. API polyglotte: un noyau Rust, exposé partout Par exemple OpenDAL, xberg, …
3. Prototyper en Python puis migrer en Rust: itérer +vite, faire performant quand on est stable
4. Sandboxing, plugins: controller du code Python non-fiable.Mais est-ce que WASM, ou les microVM ne
sont pas mieux pour ça ?
